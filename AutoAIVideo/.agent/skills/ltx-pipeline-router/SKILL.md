# AI 视频 Pipeline 决策路由器

## 本 skill 的定位

这是 AI 视频工作流的**决策层 skill**——在用户写任何单镜头 prompt 之前先用,或者跑出成片有问题时用来判断是否要切换路线。

```
ltx-world-bible / cuojia-longgu (世界观锚点)
        ↓
ltx-shot-planning (拆镜头清单 + 粗粒度 pipeline hint)
        ↓
   ┌────[本 skill] 精细决策 / 衰减红线复核 ────┐
   ↓                ↓                       ↓
ltx-t2v-prompt  ltx-i2v-prompt       ltx-flf-prompt
   ↓                ↓                       ↓
   └──→ 生成视频 ──→ 不满意? ──→ ltx-iteration-strategy
                                      ↓
                            (帧级失败诊断)
                                      ↓
                            如果诊断结论 = pipeline 物理短板
                                      ↓
                            回 [本 skill] 二次决策 → 转换路线
```

**本 skill 输出 = 单条路线推荐 + 理由 + 准备工作清单 + 下一步 skill 调用建议**。

跟其他 skill 的关系:
- **shot-planning 已经粗略给 pipeline hint**(每镜的"首尾帧策略"字段),本 skill 是**精细决策 + 衰减红线复核**——shot-planning 的 hint 只是初稿,凡是衰减风险 ≥ 4 分(见后)的镜头都应过本 skill 复核
- **不写 prompt**——那是三个 prompt skill 的事
- **不诊断帧级失败**——那是 ltx-iteration-strategy 的事
- **不评估首帧合格性**——那是 ltx-first-frame-prep 的事
- **不规划镜头序列**——那是 ltx-shot-planning 的事

本 skill 只回答一个问题:**这个镜头该走 i2v、flf 还是 t2v?**

---

## 三条 Pipeline 的本质区别

理解决策前先看清楚三条路是什么。

### t2v · text-to-video

**输入**:0 张图 + 文字 prompt
**模型工作**:完全从文字想象,包括首帧、所有中间帧、末帧
**最大优点**:零图片准备成本,文字能描述什么就能生成
**最大短板**:LTX 自己想象的首帧质量参差不齐;跨镜头一致性几乎不可控;无法锁定视觉资产

### i2v · image-to-video

**输入**:1 张首帧 + motion prompt
**模型工作**:从首帧出发,自由生成后续每一帧——**不知道终点应该长什么样**
**最大优点**:首帧已锁,起点稳定;能拿到模型主动加的"意外之喜"(如某些 seed 跑出来的步行晃动)
**最大短板**:末段衰减、漂移高发,尤其在低光暖色长时长推近场景;终点构图不可控

### flf · first-last-frame

**输入**:2 张图(首帧 + 尾帧)+ motion prompt
**模型工作**:在两张图之间插值生成中间帧——**起止被硬锁**
**最大优点**:末段衰减问题从根上消失;A→B 过程可控;跨镜头一致性最强
**最大短板**:需多出一张尾帧且首尾必须严格同风格;创意自由度低;首尾差异过大时中间帧崩

## 决策因子(3 项硬因子 + 1 项前置开关 + 2 项偏好调节)

### 前置开关 · 是否系列内容?

**这是跨越所有运动类型的元约束**,先于决策树判断。

| 用户情境 | 影响 |
|---|---|
| 单镜头一次性内容(测试、demo、零散素材) | 按主决策树 |
| 系列短剧 / IP 角色多镜头 / 广告系列 | **所有分支 flf 权重 +1 档**——一致性优先 |
| 项目宪法 skill 已激活(如 cuojia-longgu) | **同上**——跨镜头一致性是项目宪法的硬要求 |

---

### 硬因子 1 · 图片数量(决定性硬约束)

| 输入 | 候选路线 |
|---|---|
| 0 张图,只有文字想法 | **t2v** 或先回 first-frame-prep 出图 |
| 1 张首帧 | **i2v** 或先补一张尾帧走 **flf** |
| 2 张图(首帧+尾帧) | **flf** |

没图不能 i2v,没尾帧不能 flf——这一项是绝对硬约束。

---

### 硬因子 2 · 运动类型(决定性)

| 运动类型 | 推荐 | 理由 |
|---|---|---|
| **静景微动**(雪/烛/烟/布料/水/火) | **i2v** | flf 在首尾几乎相同的情况下反而出"卡顿感",中间帧无方向感 |
| **明确 A→B 过程**(推近/拉远/转身/位移/表情大变) | **flf** | 末端构图必须到位,i2v 猜不准 |
| **让模型自由发挥**(运动方向不重要) | **i2v / t2v** | flf 不给惊喜 |
| **抽象动态生成**(粒子、烟、水墨、爆炸) | **t2v** | 这些动态难以从静帧生发 |

---

### 硬因子 3 · 衰减风险计分(关键修正因子)

LTX-2.3 在以下场景**末尾衰减是物理短板**,不是 prompt 能修的。**每个 + 算 1 分,每个 ++ 算 2 分,加总**:

| 风险因子 | 权重 |
|---|---|
| 低光场景(夜景、室内暖光、暮色、阴天室内) | **++** (2) |
| 暖色主导(壁炉、烛光、暖灯、夕阳) | **++** (2) |
| 推近运动(dolly in 越接近发光体越严重) | **++** (2) |
| 时长 ≥ 5 秒 | **+** (1) |
| 高对比(冷外景 + 暖室内 / 明暗强烈对撞) | **+** (1) |
| 复杂前景物体(树干、栏杆等会被推出框) | **+** (1) |
| 含人脸 5 秒以上 | **+** (1) 身份漂移风险 |
| 含手部复杂动作 | **+** (1) |

**计分阈值**:

| 分数 | 决策影响 |
|---|---|
| 0-2 分 | 低风险,按运动类型默认路线 |
| 3 分 | 中风险,默认路线 + 备选 flf 加重 |
| **≥ 4 分** | **强烈建议 flf**——i2v 在这个分数线以上稳定失败,不要让用户先试 i2v 浪费抽卡预算 |

**实战教训**:山地小屋推到门口的镜头命中"低光++ / 暖色++ / 推近++ / 5s+ / 高对比+ / 复杂前景+ = 9 分",i2v 加再多反衰减 prompt 都救不回来。这条阈值是从血的教训蒸馏出来的。

---

### 偏好调节 1 · 终点构图确定性

不改变默认路线,但影响置信度。

| 用户表达 | 调节 |
|---|---|
| 明确说"推到 X、落在 Y、最后是 Z" | **flf 置信度 +**,且如默认是 i2v 则备选 flf 加重 |
| 模糊地说"自然推近一下"或没说终点 | i2v 置信度 + |

---

### 偏好调节 2 · 抽卡预算 + 准备工作意愿

不改变默认路线,但影响备选方案的排序。

| 偏好 | 影响 |
|---|---|
| 预算紧、要一次成 | **flf 优先**(成功率更高) |
| 预算宽、愿意 roll 3-5 次拿惊喜 | **i2v 优先** |
| 已有完美首帧,不想出尾帧 | **i2v 兜底** |
| 不愿出任何图 | **t2v 唯一选择** |

---

## 决策树(主流程)

```
Step 0 · 前置开关
   └─ 是否系列内容? → 是 → 所有 flf 选项 +1 档

Step 1 · 硬因子 1(图片数量)
├─ 0 张 → t2v(或回 first-frame-prep 出图后再决策)
├─ 2 张 → flf
└─ 1 张 → 进入 Step 2

Step 2 · 硬因子 2(运动类型)
├─ 静景微动
│   ├─ 衰减计分 ≥ 4 → i2v 首选,但备选 flf 强烈加重(实测衰减太狠时改 flf)
│   └─ 衰减计分 < 4 → i2v
├─ 明确 A→B 过程
│   ├─ 衰减计分 ≥ 4 → **强烈建议 flf**(出尾帧)
│   ├─ 衰减计分 3 → flf 推荐 / i2v 可一搏
│   └─ 衰减计分 ≤ 2 → i2v 可,flf 更稳
├─ 自由发挥 → i2v(或 t2v 如果觉得首帧也不重要)
└─ 抽象动态生成 → t2v
```

---

### 一、i2v 适用场景(10 类)

i2v 的甜区是**"首帧已锁、运动确定性弱、不需要末端构图精确"**的场景。LTX-2.3 在 i2v 上有以下 10 类已验证的舒适场景:

#### i2v-A · 纯静景微动 ⭐ 甜区中的甜区

**典型场景**:雪花飘落、烛火摇曳、烟雾上升、布料飘动、水面波纹、火焰跳动、热气蒸腾、阳光斑驳
**核心特征**:相机完全不动,只有画面内的局部元素自然循环运动
**为什么是 i2v**:flf 在首尾几乎相同的情况下会让 LTX 产生"原地踏步卡顿感";t2v 还要生成首帧,绕远路
**推荐时长**:3-5 秒
**关键 prompt 触发词**:`locked-off camera, only [element] moves`(运镜词典 ✅ 已验证)
**典型衰减计分**:0-3 分(单纯静景计分低)
**踩坑红线**:命中 ≥ 4 分衰减时优先考虑 flf

#### i2v-B · 环境氛围镜

**典型场景**:一片树叶旋转飘落、阳光透过窗帘缝隙、雨打在玻璃上、雪从树枝抖落
**核心特征**:单一元素的自然演化,无明确终点
**为什么是 i2v**:动作有"势"但无"终"——flf 锁尾帧反而破坏自然感
**推荐时长**:3-4 秒
**典型衰减计分**:1-2 分

#### i2v-C · 风吹发丝 / 衣物轻动

**典型场景**:长发在微风中、连衣裙下摆飘动、围巾轻摇、领带飘起
**为什么是 i2v**:flf 锁尾帧会让发丝/衣物的运动失去自然轨迹,反而僵硬
**推荐时长**:3-4 秒
**衰减计分**:2-3 分(发丝形变是 LTX 弱项)
**踩坑红线**:大幅运动(强风、奔跑甩发)→ 改 flf 锁起止,否则发丝糊成一团

#### i2v-D · 轻微情绪 / 表情变化

**典型场景**:眼神微转、嘴角轻扬、眨眼、缓慢呼吸、轻微吞咽
**核心特征**:幅度极小,身份漂移风险可控
**推荐时长**:3-4 秒(超过 4s 身份漂移高发)
**衰减计分**:含人脸自动 +1
**踩坑红线**:**大幅表情变化必须改 flf**(从平静到大笑、从沉思到惊讶等)

#### i2v-E · 小幅推近 / 拉远(白天非暖光)

**典型场景**:白天产品近景慢推、外景空镜慢推、人物中景慢推到面部
**核心特征**:运动幅度小,无低光/暖光衰减触发器
**推荐时长**:3-5 秒
**衰减计分**:推近 ++ 是大头,但白天非暖光场景总分通常 2-3 分
**踩坑红线**:同样的推近运动**只要场景变成低光暖光,衰减计分必飙到 4 分以上,必须改 flf**

#### i2v-F · 不确定动作的探索 ⭐ i2v 独有价值

**典型场景**:"看看 LTX 会让这张图怎么动"、"想要意外之喜"、概念探索阶段
**核心特征**:用户不知道想要什么,让模型来惊喜
**为什么必须 i2v**:flf 锁起止后模型几乎不会主动加东西,t2v 连起点都没有
**推荐时长**:3-5 秒
**实战例**:山地小屋项目中 t2.mp4 跑出来的"第一人称步行晃动"——用户没在 prompt 里要求,LTX 自己加的。这是 i2v 独有的"种子运气"价值

#### i2v-G · 食物 / 液体动态

**典型场景**:蒸汽升腾、酱料淋下、咖啡倒入、冰块融化、奶油浇上
**为什么是 i2v**:有"流动方向"的物理动态在 LTX i2v 里出片率很高
**推荐时长**:3-5 秒
**衰减计分**:通常 0-2 分
**踩坑红线**:杯子产品 360° 旋转 → 改 flf

#### i2v-H · POV / 手持模拟

**典型场景**:第一人称走路、推门、抬手取物、视线移动
**核心特征**:让 LTX 在画面里加"手持晃动 + 自然推进"的节奏感
**推荐时长**:3-4 秒
**衰减计分**:含推近 ++,加其他可能命中 4 分
**实战例**:山地小屋项目证实"`as if walking forward on foot, with the subtle natural sway of human footsteps`"配合推近触发词能跑出真实的第一人称步行感

#### i2v-I · 单物体小幅旋转 / 摇晃

**典型场景**:吊灯轻摇、风铃晃动、悬挂物随风、单页书翻动
**为什么是 i2v**:运动幅度可控,无明确终点
**推荐时长**:3-4 秒
**踩坑红线**:**整圈 360° 旋转 → 必须 flf**(i2v 旋转幅度不足是已验证规律)

#### i2v-J · 抽卡型概念验证

**典型场景**:首帧已经出来,想快速验证"这个镜头大致能不能动起来"
**为什么是 i2v**:不需要出尾帧,迭代成本最低
**推荐时长**:3 秒(只验证概念,不冲长度)
**升级路径**:概念验证通过后,如果衰减计分 ≥ 4 → 改走 flf 出正式版

---

### 二、flf 适用场景(10 类)

flf 的甜区是**"明确 A→B、衰减场景、一致性优先"**。LTX-2.3 在 flf 上有以下 10 类典型场景:

#### flf-A · 明确推近 A→B(低光暖色)⭐ flf 必选

**典型场景**:推到门口、推到人脸、推到产品 logo、推进室内
**核心特征**:衰减计分 ≥ 4 分,i2v 物理短板
**为什么必选 flf**:i2v 在这场景下加再多反衰减 prompt 都修不掉末段变暗——已实战验证
**推荐时长**:4-6 秒(flf 时长比 i2v 抗衰减强但不是无限)
**建议 last_strength**:0.85-0.90
**准备工作**:出"推近后的尾帧",同首帧风格、同光线、同场雪/烟,只改视角和构图
**实战例**:山地小屋推到门口镜头——i2v v5 仍衰减,flf 是唯一稳定路径

#### flf-B · 明确拉远 A→B / 揭示构图

**典型场景**:从特写拉到全景揭示空间、从人物拉到场景、从局部拉到整体
**为什么必选 flf**:i2v 拉远的"揭示了什么"无法控制,模型可能拉出无关内容
**推荐时长**:4-6 秒
**建议 last_strength**:0.85-0.90
**踩坑红线**:首尾差异过大(特写 → 极远景)时中间帧插值会崩,考虑拆段

#### flf-C · 产品 360° / 大幅度旋转 ⭐ flf 必选

**典型场景**:杯子/瓶子/鞋子转一圈、产品翻面、首饰转动展示
**为什么必选 flf**:i2v 默认会把旋转做得幅度极小(已验证规律——5 秒目标 360° 实际只转几度)
**推荐时长**:4-5 秒
**建议 last_strength**:0.90-0.95(强锁终态)
**准备工作**:出"旋转后的尾帧"——杯把朝右 → 杯把朝左,其他完全相同
**关键 prompt**:`rotates 360° clockwise, completing by the 4th second, then holds steady`

#### flf-D · 角色转身 / 转头

**典型场景**:从背影转到正面、从侧脸转到正脸、转头看向相机
**为什么必选 flf**:i2v 转身过程中身份漂移高发(脸/服装变化)
**推荐时长**:3-5 秒
**建议 last_strength**:0.85-0.90
**踩坑红线**:转 180° 以上(背影 → 正面)首尾差异极大,中间帧崩概率高 → 考虑拆段做 90° + 90°

#### flf-E · 大幅表情变化

**典型场景**:从平静到大笑、从沉思到惊讶、从微笑到哭泣
**为什么必选 flf**:i2v 表情演化失控,容易"哭一半笑了"或"表情糊掉"
**推荐时长**:3-4 秒(含人脸,时长越短越稳)
**建议 last_strength**:0.85
**踩坑红线**:身份/脸型必须严格一致,只改表情,不改面孔——这要靠出尾帧时的 IP 锁

#### flf-F · 场景气氛过渡(时间流逝)

**典型场景**:白天 → 黄昏、晴天 → 雨天、空房间 → 灯亮、未点燃 → 燃烧
**为什么必选 flf**:i2v 完全无法跨大幅度时间/状态变化
**推荐时长**:5-7 秒(可以做得长一些,因为变化本身需要时间感知)
**建议 last_strength**:0.80-0.85(稍低,让中间帧有"过渡的自由")
**踩坑红线**:首尾光线/色温差异过大时,中间帧色调会跳变 → 考虑拆段或加中间帧

#### flf-G · 跨镜头一致性优先 ⭐ flf 必选

**典型场景**:系列短剧、IP 角色多镜头、广告系列、品牌 visual identity 镜头
**为什么必选 flf**:首尾双端锁 + 跨镜头共用世界观锚点 = 最强一致性保险
**推荐时长**:按各镜头需要(典型 4-5 秒)
**建议 last_strength**:0.90
**协作建议**:项目宪法 skill(如 cuojia-longgu)激活时,每镜默认走 flf
**踩坑红线**:每镜的首尾帧必须用同一套"黄金种子 + 共用 prompt 锚点"出图

#### flf-H · 物体位移 / 出入画

**典型场景**:物体从 A 处移到 B 处、人物入画 / 出画、车辆穿越画面
**为什么必选 flf**:i2v 不知道终点位置,容易"移一半停了"
**推荐时长**:3-5 秒
**建议 last_strength**:0.90
**踩坑红线**:位移轨迹复杂(曲线、跨越多个深度层)→ 拆段

#### flf-I · 倒带 / 循环 / 首尾一致

**典型场景**:首尾完全相同的循环动画、来回往复的运动、节拍式动作
**为什么必选 flf**:唯一能稳定做"首尾相同"的路径
**推荐时长**:3-5 秒
**建议 last_strength**:0.95(极强锁)
**特殊用法**:同一张图同时作为首帧和尾帧,中间让 LTX 编一段"出去又回来"的运动

#### flf-J · 失败转换兜底场景

**典型场景**:i2v 已稳定失败(3 次以上同一种失败),需要换路线
**为什么 flf**:99% 的 i2v 物理短板失败转换都是改 flf
**推荐时长**:同原 i2v 镜头,但若衰减严重可缩 1 秒
**准备工作**:从原 i2v 跑出的最好那版抽出"中段"作为尾帧候选(零额外出图成本)

### 三、t2v 适用场景(6 类)

t2v 的甜区是**"无图、抽象、概念探索"**。LTX-2.3 在 t2v 上有以下 6 类场景:

#### t2v-A · 完全抽象动态

**典型场景**:水墨晕染开、粒子聚散、烟雾形态变化、能量光效、几何变换
**为什么必选 t2v**:没有锁定视觉资产,这类画面从静帧生发反而限制创意
**推荐时长**:3-5 秒
**踩坑红线**:复杂程度高时 LTX 自由发挥度太大,出片率低

#### t2v-B · 快速概念验证 / 灵感探索

**典型场景**:"这个想法跑出来什么效果?"、还在头脑风暴阶段、没准备图
**为什么必选 t2v**:出图都嫌慢,直接 t2v 看大致效果
**推荐时长**:3 秒(只验证)
**升级路径**:验证通过后,如果想要稳定版本 → 提取一帧作为首帧改走 i2v

#### t2v-C · 风格化转场镜头

**典型场景**:镜头穿越云层 / 星空 / 水面、抽象 morph 转场、画面被光吞没
**为什么必选 t2v**:转场镜头不需要锁定起点和终点,t2v 自由度反而是优点
**推荐时长**:2-3 秒(转场都短)

#### t2v-D · 元素生成型动态

**典型场景**:雷雨、雪崩、爆炸、火山喷发、海浪冲击、龙卷风
**为什么必选 t2v**:这些动态从单一静帧难以生发,t2v 直接生成动态时序更好
**推荐时长**:3-5 秒
**踩坑红线**:复杂场景 + 大规模动态 = LTX 出片率最低的场景之一,可能要 roll 多次

#### t2v-E · 临时占位镜 / 工作流过渡

**典型场景**:shot-planning 阶段还没出图、给客户看 mock、剪辑流程占位
**为什么必选 t2v**:出图工作还没做,但要先看动态节奏
**推荐时长**:同最终镜头预期时长
**升级路径**:占位通过后,正式版按场景重新决策

#### t2v-F · 纯文字想象内容

**典型场景**:超现实场景、梦境、抽象意识流、纯诗意画面
**为什么必选 t2v**:文字描述远比图片精准,首帧反而限制了想象
**推荐时长**:3-5 秒

### 四、决策禁区(三条路都不该走 AI 视频的场景)

有些镜头**当前 LTX-2.3 任何 pipeline 都做不好**,本 skill 应该建议"考虑真拍 / 改镜头设计 / 后期合成":

| 禁区场景 | 为什么 LTX 做不了 | 替代建议 |
|---|---|---|
| 长台词 / 复杂对白 | LTX 不擅长长 lip-sync | 用 LTX Pro 的 LipDub pipeline,或后期对口型 |
| 复杂手部动作(乐器演奏、写字、手语) | 手指必崩 | 改中景遮挡手部,或后期合成 |
| 完整人体大幅动作(舞蹈、武打、奔跑全身) | 肢体几何破坏 | 拆成多个特写镜头,或真拍 |
| 多人交互(两个以上人物对话/接触) | 人物融合 | 拆成单人镜头交叉剪辑 |
| 文字内容(招牌、字幕、印刷品) | 文字必糊 | 后期叠加文字 |
| 镜面 / 透明物体反射逻辑 | 反射几何必崩 | 改避开反射的角度 |
| Dutch tilt / 横滚镜头 | 画面旋转必崩(运镜词典已证) | 用静态 Dutch tilt 首帧 + 静止镜头 |
| Dolly zoom / Vertigo shot | LTX 完全做不出 | 用其他方式制造心理张力 |
| 超过 10 秒单镜头 | 累积漂移必崩 | 拆成多个 5 秒段 + NLE 拼接 |
| 360° 环绕物体一圈 | 3D 一致性弱项,绕半圈背面就崩 | 拆段做 45° 弧 + 多段拼接 |

**遇到禁区场景时,本 skill 输出**:"建议不走 AI 视频路径"+ 替代方案,而不是硬选 pipeline。

## 触发模式 1 · 初始选型

用户描述一个还没生成的镜头想法时:

### Step 1 · 提取场景特征

读用户消息,识别:
- 是否系列内容(前置开关)
- 有几张图(硬因子 1)
- 运动类型属于哪一类(硬因子 2,对照场景图谱定位)
- 衰减风险因子命中哪些 + 计分(硬因子 3)
- 终点构图明示程度(偏好调节 1)
- 预算和准备意愿(偏好调节 2)

**用户没说的不要瞎猜——主动追问**。但只问真正影响决策的(通常是图的数量和运动意图)。

### Step 2 · 对照场景图谱 + 决策树

先看场景描述能否直接归类到场景图谱的某一类(如"推到门口"→ flf-A;"雪在下"→ i2v-A);如果对得上,直接走对应推荐。如果属于跨类或边缘场景,走主决策树。

### Step 3 · 输出推荐

按"输出格式"节生成完整推荐。

## 触发模式 2 · 失败转换

用户跑出来一版成片不满意,问"是不是该换 pipeline"或描述失败现象时:

### Step 1 · 跟 iteration-strategy 划清边界

**先问自己:这是 pipeline 物理短板,还是 prompt/seed 问题?**

| 失败现象 | 性质 | 处理 |
|---|---|---|
| 末尾衰减(变暗、雪量减弱、光萎缩、色调漂移) | **i2v 物理短板** | 本 skill 建议改 flf |
| 运动方向错(想推近,模型在转头) | **i2v 物理短板**(模型猜错) | 本 skill 建议改 flf |
| 终点构图不到位(说推到门口,只推了一半) | **i2v 物理短板** | 本 skill 建议改 flf |
| 旋转幅度严重不足(目标 360° 实际几度) | **i2v 物理短板** | 本 skill 建议改 flf |
| 跨镜头身份漂移(系列里人脸变了) | **i2v 物理短板** | 本 skill 建议改 flf |
| 大幅表情演化失控(笑一半变哭) | **i2v 物理短板** | 本 skill 建议改 flf |
| flf 中间帧色调不一致 | **flf 短板**(首尾图色调本就不一致) | 回 first-frame-prep 重出首尾 |
| flf 中间帧运动不自然(瞬移感) | **flf 短板**(首尾差异过大) | 拆段,或加中间帧 |
| flf 出来太僵硬,没有 i2v 的灵动 | **flf 短板**(last_strength 太高) | 调参,不换 pipeline |
| t2v 跨镜头不一致 | **t2v 短板** | 改走 flf(先出首尾帧) |
| t2v 首帧不合预期 | **t2v 短板**(模型自由发挥) | 改走 i2v(先出图) |
| 单帧扭曲、手指崩、文字糊 | spatial 类失败 | **不归本 skill**,回 iteration-strategy |
| 闪烁、蠕动 | temporal 类失败 | **不归本 skill**,回 iteration-strategy |
| 风格不对、节奏不对 | intent 类失败 | **不归本 skill**,回 iteration-strategy |
| 同 prompt 单次抽卡崩 | 抽卡运气 | **不归本 skill**,回 iteration-strategy 重 roll |

**判断红线**:用户必须先用同 prompt 跑了 2-3 次都同一种失败,确认稳定失败后,才进本 skill 的转换决策——具体重 roll 的操作执行回 iteration-strategy。

### Step 2 · 转换决策

```
当前 pipeline · 失败类型 → 推荐转换
────────────────────────────────────────
i2v · 末段衰减 / 终点飘 / 旋转幅度不足 → flf
i2v · 跨镜头不一致 → flf
i2v · 大幅表情失控 / 大幅身份漂移 → flf
i2v · 静景微动也崩 → 不换 pipeline,回 iteration-strategy 调 motion 或缩时长
i2v · 概念探索/惊喜不够 → 不换 pipeline,多 roll 几个 seed

flf · 中间帧色调不一致 → 不换 pipeline,回 first-frame-prep 重出首尾
flf · 中间帧瞬移感 → 拆成多段独立镜头(各自 i2v 或 t2v)
flf · 太僵硬 → 不换 pipeline,回 iteration-strategy 调 last_strength
flf · 仍然衰减(罕见) → 检查首尾图本身有无亮度差,重出尾帧

t2v · 首帧不合预期 → 改走 i2v(先出图)
t2v · 跨镜头不一致 → 改走 flf(先出首尾帧)
t2v · 抽象效果不到位 → 不换 pipeline,改 prompt
```

### Step 3 · 输出转换建议

按"输出格式"节生成,但**第一节标题改为"Pipeline 转换建议"**,且必须包含:
- 当前路线失败的根本原因
- 新路线为什么能修
- 转换需要做的准备工作(比如出尾帧)
- 沉没成本是否可救——比如当前 i2v 成片前段健康,可以剪出来作为 NLE 备用素材

→ flf prompt 可复用 i2v 已写好的运动描述(步行晃动 / 雪量 / 暖光等),只需删除"反衰减"相关 prompt(flf 不需要)

## 本路线的风险预警

- 首尾两张图必须严格同风格,差一点中间帧会出诡异过渡
- last_strength 调到 0.85-0.90,太低末帧锁不住,太高中间帧会僵硬
- 如果首尾构图差异过大(远景→特写跨度过猛),考虑拆成两个独立镜头各自 i2v
```

### 示例 3 · 失败转换 · i2v 末段衰减 → flf

**用户输入**:"i2v 跑了 3 次同一个推近 prompt,每次末段都变暗,天空变黑,木屋外墙变深"

```
## Pipeline 转换建议

**当前路线**:i2v
**推荐转换为**:flf
**置信度**:高
**场景图谱归类**:flf-J(失败转换兜底)+ flf-A(明确推近 A→B)

**当前路线失败原因**:
低光暖色推近场景是 LTX-2.3 i2v 的物理短板——模型把"推近发光物体"误读为"白天 → 黄昏"的时间流逝叙事,自动压暗背景天空和外立面。3 次同一种失败 = 稳定失败,不是抽卡运气,prompt 加再多反衰减约束也突破不了。

**新路线为什么能修**:
flf 把末帧画面硬锁——末帧亮度由你出图时决定,LTX 不再"自由发挥末段"。衰减问题不是被修复,是被绕开。

---

## 备选方案

**备选 1**:接受当前最好版本 + NLE 后期救
- 什么情况下选它:用户没有 flf 链路或不愿出尾帧
- 代价:后期工作量,且只能修亮度

**备选 2**:i2v 缩到 3 秒
- 什么情况下选它:愿意牺牲推近幅度
- 代价:推不到门口

---

## 准备工作清单

- [ ] **出"门口尾帧"** —— 同首帧风格,只改视角和构图
- [ ] 保留当前 i2v 最好那版的 0-3s 片段作为备用素材(沉没成本可救)
- [ ] 记下当前 i2v 最好那版的 seed(即便 pipeline 换了,这个 seed 在 flf 下可能仍然是黄金种子)

## 下一步 skill 调用

→ 先回 `ltx-first-frame-prep` 处理尾帧出图约束
→ 出完尾帧进入 `ltx-flf-prompt` 写 motion prompt
→ 跨镜头复用建议:这次出尾帧的方法学进项目宪法 skill(如 cuojia-longgu)沉淀

## 本路线的风险预警

- flf 不会复刻 i2v 时模型主动加的"意外之喜"(比如某些 seed 跑出来的步行晃动)。如果想保留某种意外动效,要在 flf prompt 里显式描述出来
- 如果首尾差异巨大,中间帧插值会崩——先评估两张图构图差异是否合理
```

### 示例 5 · 失败转换 · flf 中间帧瞬移 → 拆段

**用户输入**:"flf 跑出来转身镜头,从背影到正面,中间帧像瞬移一样不连贯"

```
## Pipeline 转换建议

**当前路线**:flf
**推荐转换为**:拆成两个独立镜头(背影→侧脸 + 侧脸→正面,各自 flf)
**置信度**:高
**场景图谱归类**:flf-D(角色转身)+ flf 短板"首尾差异过大"

**当前路线失败原因**:
背影 → 正面是 180° 转身,首尾构图差异极大,LTX 在两帧之间插值时找不到平滑路径——这是 flf 已知的"首尾差异过大时中间帧崩"短板,不是 prompt 问题。

**新路线为什么能修**:
拆成 90° + 90° 两段,每段首尾差异减半,LTX 插值压力大幅降低。两段拼接后视觉上仍是连贯的 180° 转身。

**备选 1**:不拆段,但在 flf 之外加一张"侧脸中间帧"作为锚点(三帧 flf,如果工具支持)
- 什么情况下选它:工具支持多关键帧 flf(LTX 2.3 Pro 部分支持)
- 代价:多出一张图

**备选 2**:接受当前瞬移感,后期 NLE 加快速运动模糊掩盖
- 什么情况下选它:转身镜头不是主要叙事重点
- 代价:画面质感打折

## 准备工作清单

- [ ] **出"侧脸中间帧"** —— 角色同 IP、同光线、同时刻,只改头部朝向 90°
- [ ] 拆分时间分配:5 秒原镜 → 2.5 秒 + 2.5 秒两段
- [ ] 拼接预留:第一段尾帧 = 第二段首帧,确保剪辑点无跳跃

## 下一步 skill 调用

→ 出侧脸中间帧前回 `ltx-first-frame-prep` 检查 IP 一致性
→ 出图后分别进入 `ltx-flf-prompt` 写两段 motion prompt
→ 长期沉淀:转身镜头默认拆段,进项目宪法 skill(如 cuojia-longgu)

## 本路线的风险预警

- 两段拼接处的剪辑点处理:用 0.3s 交叉溶解或硬切都行,避免运动停顿
- 跨段身份一致性:用同一 seed 起手两段 flf

### 示例 6 · 不归本 skill 处理

**用户输入**:"我跑 i2v 出来人物的手指扭曲了"

```
## 不是 Pipeline 决策问题

这是 **spatial 类失败**(类型 A · Warping / 手指崩),不属于 pipeline 物理短板,换 flf 也救不了——flf 同样会让首尾之间的手指扭曲。

**正确处理路径**:
→ 回到 `ltx-iteration-strategy` 走类型 A 救法:降复杂度 / 改首帧 / 拆短时长 / 重 roll
→ 如果首帧本身手指就崩,回 `ltx-first-frame-prep` 重出首帧
→ 如果是动作复杂度太高,回 `ltx-i2v-prompt` 简化动作描述
→ 长期方案:复杂手部动作属于本 skill"决策禁区"——考虑改镜头设计(中景遮挡手)、真拍、或后期合成

本 skill 在这里没建议——pipeline 选型已经正确,失败在别处。
```

---

## 决策原则

### 原则 1 · 不要为了用 flf 而用 flf

flf 不是万能药。**静景微动用 flf 反而出"卡顿感"**,因为首尾几乎一样的两张图让 LTX 插值时无方向感。**i2v 在静景微动里是更舒服的选择**(场景图谱 i2v-A)。

### 原则 2 · 衰减计分 ≥ 4 分宁严勿松

低光 + 暖色 + 推近这种组合在 LTX-2.3 是稳定失败区——**碰到就建议 flf,不要让用户先试 i2v 浪费抽卡预算**。教训来自实战。

### 原则 3 · 不替用户做链路判断

本 skill 不知道用户用 LTX Studio / ComfyUI / Fal / Replicate 还是什么。**只输出"场景上该走哪条",链路是否支持让用户自己判断**。如果用户主动说"我的链路不支持 flf",再走备选方案。

### 原则 4 · 失败转换前必须验证稳定失败

跑 1 次 i2v 失败就说"换 flf"是错的——可能下次 seed 好就过了。**必须让用户先按 iteration-strategy 重 roll 2-3 次,确认 3 次都同一种失败**,才走转换路径。本 skill 不执行重 roll(那是 iteration-strategy 的事),只在确认稳定失败后做决策。

### 原则 5 · 转换不是抛弃旧路线产出

i2v 跑出来的"最好那一版"即便末段崩,前段可能完全可用。**转换 flf 时提醒用户保留旧版前段**——可以作为 NLE 备用素材,或者其前段对应的 seed 仍然是黄金资产。i2v 的 seed 经常在 flf 下仍能复用。

### 原则 6 · 决策禁区不强行选 pipeline

遇到长台词、复杂手部、多人交互等禁区场景,**不要从 i2v/flf/t2v 里挑一个凑合**——直接告诉用户"建议不走 AI 视频"+ 替代方案。硬上的代价是用户多 roll 10 次都救不回来。

### 原则 7 · 系列内容默认 flf 偏好 +1 档

项目宪法 skill 激活、或用户明示做系列内容时,**所有运动类型默认 flf 偏好上调一档**——即便单镜头看起来 i2v 也能做,跨镜头一致性会逼着你最终走回 flf。一开始就走 flf 比中途切换成本低。

## 写作风格

- 输出始终中文(除非用户明确要英文)
- 推荐必须给出**单一首选 + 备选**,不能只列三个让用户挑——那是把决策推回用户
- 决策因子必须明示命中情况和计分,不能笼统说"适合 flf"
- 场景图谱归类必须显式标注(如"i2v-A"、"flf-C")——方便后续迭代和经验沉淀
- 不写 prompt;如果用户已经要 prompt,提示"先决策,再去 ltx-X-prompt skill"
- 不评价用户的镜头创意("这个想法不错"→错。直接判断 pipeline)

## 输出纪律

- 不调用 storage
- 不生成反馈 Artifact
- 不主动调用其他 skill(本 skill 只输出"调哪个",用户自己进)
- 输出完即停
