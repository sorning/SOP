# SOP · 短视频运营系统

一个把 **标准作业程序(SOP)** 从静态文档进化成 **可执行流程引擎** 的仓库。
核心是一个「数据飞轮」:每天驱动生产、采集播放量、分析算法规律,最终收敛到一个目标 —— **播放量 → YouTube / Facebook 广告分成**。

> 在线可视化页面:由 GitHub Pages 自动部署 `index.html`(数据目录不公开)。

## 目录结构

| 路径 | 作用 |
|------|------|
| `CLAUDE.md` | 给 AI 助手看的项目说明与文档约定 |
| `.claude/skills/daily-video/SKILL.md` | 每日短视频生产与复盘的交互式流程技能 |
| `数据/播放量记录.csv` | 逐条原始数据(每日采集后追加) |
| `数据/分析日志.md` | 每日分析结论与算法假设的累积记录 |
| `index.html` | 项目可视化页面(Tailwind CDN + JS) |
| `.github/workflows/pages.yml` | GitHub Pages 部署流程(仅发布 `index.html`) |

## 核心理念:数据飞轮

```
生产视频 → 采集播放量 → 分析算法规律 → 落到变现动作 → 指导明日生产 → ……
```

- **三个核心 niche(固定优先级)**:`home` → `ring` → `mega hall`
- **两个变现平台**:YouTube / Facebook
- **唯一北极星指标**:播放量(涨粉、互动只是手段,播放量才是钱)

## 每天怎么用

在 Claude Code 里说「**开始今天的视频**」或输入 `/daily-video`,技能会按四个阶段带你走:

1. **生产提醒** —— 按 `home → ring → mega hall` 顺序逐个打勾完成
2. **采集数据** —— 逐条询问上一日各平台播放量,追加写入 `数据/播放量记录.csv`
3. **统计 & 找规律** —— 读取全部历史数据,横向对比 + 趋势 + 可验证的算法假设
4. **落到变现** —— 翻译成「哪个 niche / 平台值得加码」的具体行动建议

## 约定

- 所有面向用户的文档默认用 **中文** 撰写。
- 这是文档仓库,**没有** 构建 / 编译 / 测试流程,产物就是 `.md` 文档和 `index.html`。
- 提交信息使用中文;推送遵循会话指定的功能分支,不直接推 `main`。
- 数据文件每次更新后记得 `git commit`,长期积累才有分析价值。
