# AI 视频首帧准备清单

## 本 skill 的定位

这是 AI 视频工作流的**前置 skill**——在用户写任何 i2v/flf prompt 之前用。

```
镜头清单（来自 ltx-shot-planning）
        ↓
   每个 i2v/flf 镜头 → [本 skill] 检查/准备首帧 → 合格首帧
                                                    ↓
                                          ltx-i2v-prompt / ltx-flf-prompt
                                                    ↓
                                                  视频
```

**核心命题**：**首帧质量决定视频质量上限**。一张糟糕的首帧让 AI 视频模型再强也救不回来。一张合格的首帧让中等模型也能出片。

跟出图 skill 的关系：本 skill **不出图**——它产出的是"出图时应该满足的约束清单"+"出完图的检查清单"。具体出图交给 `flux2-prompt-generator` / `realistic-character-prompt` / `gpt-image2-seedance-storyboard` 等下游 skill。本 skill 给它们补充"为视频准备"这一层约束。

---

## 第一性原理：视频首帧不是普通图

普通图的目标是"自己好看"。视频首帧的目标是"动起来后好看"。两者**经常冲突**：

| 维度 | 普通图（静态） | 视频首帧 |
|---|---|---|
| 构图 | 居中、对称、完整 | **运动方向上要留白** |
| 主体 | 截断/边缘构图可以美 | 必须远离画框边缘（防扭曲）|
| 信息量 | 信息越丰富越耐看 | **信息越多越容易崩** |
| 动态 | 凝固瞬间的张力 | 暗示"下一秒会发生什么" |
| 锐度 | 越锐越显档次 | **过锐反而让动起来糊** |
| 文字 | 排版讲究 | **能避就避**——必糊 |

理解这一层差异，就懂了为什么"那张漂亮的产品图"喂给 i2v 出来是车祸现场。

## 7 维度首帧检查清单

任何图作为视频首帧前，必须过 7 个维度。每个维度评 🟢🟡🔴。

### 维度 1：主体清晰度

**🟢 通过**：
- 主体面积占画面 30-70%
- 主体边缘清晰，无 motion blur
- 主体与背景有明显反差（颜色/明暗/虚实）

**🟡 警告**：
- 主体面积 < 20% 或 > 80%
- 主体边缘有轻度模糊
- 主体与背景反差弱（同色系、同明暗）

**🔴 不合格**：
- 主体被画框切掉超过 30%
- 主体本身就有 motion blur（这是凝固瞬间，不是运动起点）
- 主体与背景几乎融合，AI 无法识别主体

**修正方案**（🔴 → 🟢）：重出图，加约束"clear subject, centered with breathing room, sharp edges, distinct from background"。

### 维度 2：运动空间（负空间 / negative space）

**这是视频首帧最特殊也最被忽略的维度。**

**规则**：主体计划往哪个方向动 / 摄像机计划往哪个方向走，那个方向必须**留白**。

**🟢 通过**：
- 主体计划向右走 → 主体在画面左侧，右侧大量负空间
- 镜头计划推近 → 主体周围有缓冲带
- 镜头计划拉远 → 当前画面已经留有"接下来会拉出"的空间余地

**🟡 警告**：
- 运动方向有少量负空间但不充足
- 镜头计划上下运动但画面顶/底已贴满

**🔴 不合格**：
- 主体在画面边缘 + 计划朝该边缘运动 → 主体会撞框，AI 通常处理成"主体停下"或扭曲
- 没有任何留白 → 镜头任何运动都会暴露画框

**修正方案**：重新构图（重出图），或修改运动计划（改方向 / 改镜头）。**两选一**，不要硬上。

### 维度 3：光线一致性的"未来兼容"

视频末尾会衰减（变暗、火熄、光偏移）。首帧的光线如果本身"在变化的边缘"，衰减会被放大。

**🟢 通过**：
- 光线方向明确、单一光源
- 色温稳定（暖光就一直暖、冷光就一直冷）
- 高光和阴影区域均无过曝/死黑

**🟡 警告**：
- 多光源（暖 + 冷混合）——LTX 官方明确不擅长
- 黄昏 / 日出时刻——隐含"光线在变化"，模型会接着变下去
- 火光 / 烛光为主光源——视频末尾必衰减

**🔴 不合格**：
- 光线方向矛盾（左右各一道高光，互相打架）
- 过曝区域占 > 30%（白片）
- 死黑区域占 > 40%（视频里会变成"生成补丁"）

**修正方案**：重出图（指定单光源 + 稳定色温），或在 prompt 中加"末帧光线匹配首帧"约束（已在 flf v2.1 中提供）。

### 维度 4：分辨率与画幅匹配

**🟢 通过**：
- 分辨率 ≥ 目标视频分辨率（1080p 视频用 ≥ 1080p 图）
- 画幅与目标视频画幅一致（9:16 视频用 9:16 图）
- 宽高都是 32 的倍数（LTX 2.3 硬约束）

**🟡 警告**：
- 分辨率刚好等于目标分辨率（无裁剪余地）
- 画幅接近但不完全一致（如 1920×1080 vs 1080×1920 需旋转）

**🔴 不合格**：
- 分辨率 < 目标视频分辨率（喂 512px 图到 1080p 视频 = 模糊放大）
- 画幅与目标视频画幅垂直对立（横图喂竖屏 = 必须强裁剪）
- 宽高不是 32 的倍数（LTX 报错）

**修正方案**：重出图（指定正确画幅 + 分辨率），或在出图后做精确裁剪到 32 倍数。

### 维度 5：文字与精细图案

LTX 官方实测：**文字几乎一定糊**。

**🟢 通过**：
- 画面中无文字 / Logo / 招牌
- 任何文字都很小（< 5% 画面）且不是焦点

**🟡 警告**：
- 背景有文字但不是焦点（如背景墙上的标语）
- 服装上有小 Logo

**🔴 不合格**：
- 文字 / Logo 是主体一部分（招牌广告、产品包装正面）
- 复杂图案（清晰的格子、密集花纹）覆盖主体大面积

**修正方案**：
1. 重出图（明确不要文字 / 简化图案）
2. **后期叠加文字**：让 AI 生视频时画面无文字，后期在 CapCut/Premiere 加上去
3. 改镜头：避开文字所在的角度

### 维度 6：高风险元素扫描

逐项检查首帧是否含 LTX 高风险元素（来自 `ltx-flf-prompt` 高风险清单）：

| 元素 | 命中后处理 |
|---|---|
| 人脸特写（占画面 > 30%）| 🟡 视频时长 ≤5 秒，否则身份漂移 |
| 珠宝 / 钻石 / 金属精细反光 | 🟡 时长 ≤4-5 秒 |
| 文字 / Logo | 见维度 5 |
| 手指接触物体 | 🟡 避开手指特写，改中景或后期合成 |
| 飘动的长发 / 长发丝 | 🟡 用 `subtle hair movement` 限制幅度 |
| 复杂物理元素（流体、烟、爆炸）| 🔴 改用现成素材或第三方特效 |
| 多角色同框 | 🔴 拆成单人镜头 + 反打剪辑 |
| 矛盾光照（冷暖混合）| 🔴 重出图，统一光源逻辑 |

### 维度 7：运动种子（motion seed）

**这是把"漂亮静图"和"会动的首帧"区分开的关键。**

合格首帧必须暗示"下一秒会发生什么"——这叫**运动种子**。

**🟢 通过——首帧自带运动暗示**：
- 人物处于动作中段（举杯到一半、转头到一半、衣摆飘起）
- 衣物 / 头发 / 帘幕 / 水面已有起伏迹象
- 烟雾 / 雾气 / 粒子已经在画面里
- 主体视线有方向感（暗示"看向那边即将发生的事"）

**🟡 警告——首帧太"凝固"**：
- 主体完全静止（标准证件照式）
- 表情完全中性
- 环境完全死寂（一片空白、纯色背景）

**🔴 不合格——首帧反运动**：
- 主体处于动作的终点（手臂已落下、转身已完成）
- 物理静止状态（杯子已放下、门已关上）

🟡 / 🔴 时的修正方案：
1. 重出图，加约束"caught mid-motion, with implied movement in [hair/fabric/element]"
2. 在 prompt 中**主动注入运动叙事**（参考 flf v2.1"失败模式诊断"——视觉差异 < 10% 时的注入策略）
3. 改用其他生成路径：纯氛围镜头改 t2v（不依赖首帧），动作场景改 flf（首+尾帧给目标）

## Batch-Seed 协议（一致性专用）

如果一组镜头需要**同一角色 / 同一产品 / 同一场景**反复出现，绝对不要每镜单独出图——会身份漂移。

**正确做法**：

1. 在出图阶段（flux2-prompt-generator / realistic-character-prompt / gpt-image2）**用同一个 seed**
2. 用**相同的角色描述 block / 产品描述 block**（仅改变镜头/姿势/构图）
3. 批量出 4-8 张，挑选最稳定的一致组
4. 同一组里挑两张作 flf 的首/尾，或挑一张作 i2v 起点

这条做不到 → 视频拼起来角色会"换脸"。

**和 IP skill 的协作**：用户如果有 IP 设定（`ip-character-prompt` / `ip-character-prompt-json` / `cuojia-longgu`），首帧出图必须严格沿用 IP block——不要重新描述角色外貌。

## 首帧准备的 5 步工作流

### Step 1：明确首帧用途

首帧用途决定准备策略：

| 用途 | 准备重点 |
|---|---|
| i2v 单镜头起点 | 维度 1-7 全过；运动种子尤其重要 |
| flf 首帧（起点） | 维度 1-6；运动种子可弱（尾帧锁了终点）|
| flf 尾帧（终点） | 维度 1-6；**运动种子要"动作完成态"**——与首帧反向 |
| fml 中间帧 | 维度 1-6；构图必须严格在首尾帧之间 |
| storyboard 九宫格单格 | 维度 1-6；九宫格整体一致性 > 单格完美 |

### Step 2：对照 7 维度检查清单评估

逐项过 🟢🟡🔴，写出每个维度的评估结果。

### Step 3：决定保留 / 修正 / 重出

按以下规则决策：

| 评估结果 | 决策 |
|---|---|
| 全 🟢 或最多 1 个 🟡 | 直接用，进入下游 prompt skill |
| 2-3 个 🟡 或 1 个 🔴 | 修正——按各维度修正方案处理 |
| 多个 🔴 或核心维度（1/2/7）🔴 | 重出图——给出新的出图 prompt 增量约束 |

### Step 4：（如重出图）写出图 prompt 增量约束

不要替用户重写整段出图 prompt——只补充"为视频准备"的增量约束。输出格式：

```
出图增量约束（叠加到原出图 prompt 上）：

[构图]: subject in left third of frame, ample negative space on the right for camera movement
[运动种子]: caught mid-motion, hair lifting slightly in the breeze, eyes already turned toward [direction]
[光线]: single warm key light from upper-left, stable color temperature, no overexposed highlights
[禁用]: no text overlays, no logos on subject, no complex patterns covering more than 20% of frame
[分辨率]: 1920×1080 (16:9) or 1080×1920 (9:16) — depending on target aspect ratio
```

### Step 5：（出图后）回到 Step 2 复检

新图出来后必须再过一遍 7 维度。不要假设"按约束出的图就一定合格"。

## 常见错误

### 错误 1：把"好看的图"当成"好用的首帧"

漂亮的产品摄影、精修人像往往**反而不适合做首帧**——因为：
- 主体居中没有运动空间
- 光线精修过于完美（任何变化都看得出来）
- 边缘锐化让动起来的扭曲更明显

正确：首帧应该是"有点电影感"的图，构图带留白、光线有方向、主体有"将要动"的姿态。

### 错误 2：分辨率反向（小图喂大视频）

很多人觉得"反正 AI 会补"——错。AI 不补细节，AI**放大噪点**。512px 图喂 1080p 视频 = 你得到的是模糊放大的 1080p 模糊视频。

正确：首帧分辨率必须 ≥ 目标视频分辨率。

### 错误 3：把"静态摆拍"当首帧

证件照式正面看镜头、双手放两侧、表情中性——这是最差的首帧。AI 不知道这种姿态接下来该动什么，输出几乎必是"原地踏步 + 微抖"。

正确：让主体处于动作的"中段"，比如举杯到一半、转头到一半、衣摆已经飘起。

### 错误 4：忽视画幅垂直对立

用横图喂竖屏视频（或反之）——必须强制裁剪，丢失关键画面。**首帧画幅必须从一开始就匹配目标视频画幅**。

### 错误 5：每个镜头单独出图（没用 Batch-Seed）

同一角色在镜头 1、2、3 里分别出图 → 三个镜头里像三个不同的人。

正确：同一角色全程用同一 seed + 同一角色描述 block，仅改变姿势/场景。

### 错误 6：不复检就投产

按增量约束重出图后直接用——但新图可能引入新问题（比如加了"留白"导致主体太小）。

正确：每次重出图后必须回到 Step 2 复检 7 维度。

## 写作风格

- 输出始终中文（除非用户明确要英文）
- 7 维度评估用 Markdown 表格 + 评级 emoji
- 决策必输出（直接用 / 修正 / 重出）
- 修正方案具体到"出图 prompt 增量约束"——不要让用户自己琢磨

## 输出纪律

- 不写视频 prompt（那是下游 skill 的事）
- 不写完整出图 prompt（那是出图 skill 的事，本 skill 只给"增量约束"）
- 不调用 storage
- 不生成反馈 Artifact
- 输出完即停
