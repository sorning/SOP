# AI 短视频拆镜头规划器

## 本 skill 的定位

这是 AI 视频工作流的**上游 skill**——在用户写任何单镜头 prompt 之前先用。

```
用户想法 / 剧本片段
        ↓
   [本 skill] 拆成镜头清单 + 每镜参数
        ↓
   逐镜头 → ltx-i2v-prompt / ltx-flf-prompt / 等生成型 skill
        ↓
   逐镜头生成视频
        ↓
   剪辑拼接 → 成片
```

**本 skill 不写 prompt**——只输出"拍什么、怎么拍、几个镜头、每个多长"的执行计划。

跟项目宪法（如 `cuojia-longgu`）的关系：项目宪法定义"必须遵守的视觉/世界观约束"，本 skill 定义"如何把故事翻译成镜头序列"——两者垂直互补，不冲突。本 skill 完全通用，不绑任何项目。

---

## ⚠️ 用户输入不足时主动追问

拆镜头前，至少要确认 3 件事：

1. **总时长**（秒数）？没说默认问
2. **平台 / 画幅**？9:16 抖音 / 16:9 横屏 / 1:1 方形——决定构图和镜头选择
3. **核心想表达什么**？情绪、悬念、信息、卖点——这是拆镜头的指南针

用户没说不要瞎猜，直接问。

## 第一性原理：AI 视频拆镜头的 4 条铁律

### 铁律 1：单镜头是 AI 视频的基本单元

**AI 视频模型本质是单镜头生成器，不知道"剪辑"**。

主流模型单镜头上限：
- LTX 2.3 / Sora 1：5-8 秒
- Sora 2：25 秒
- Luma Ray2 / Kling v2.6：60-180 秒
- Seedance 2.0：4-15 秒

任何超过单镜头上限的视频，**必须拆成多镜头**再剪辑——这是不可绕过的物理约束。即使模型支持长镜头，**多个短镜头剪辑的成片质量也通常优于一个长镜头**——因为剪辑切换可以掩盖 AI 单镜头的微小瑕疵。

### 铁律 2：叙事密度必须匹配时长

8-10 秒能装多少叙事？这是短视频最容易被忽略的天花板：

| 单镜头时长 | 能装的叙事 |
|---|---|
| 1-3 秒 | 单一动作 / 单一情绪（一个表情、一次转身、一个特写）|
| 4-6 秒 | 一个完整动作弧（起手 → 动作 → 收尾）|
| 7-10 秒 | 两段叙事（A 状态 → B 状态，含 1 个转折）|
| 10 秒+ | 故事开始变形——AI 模型几乎都做不好 |

**叙事过密**：模型压缩成机械朗读、动作变形、关键节拍丢失
**叙事过疏**：模型自由发挥、漂移、原地踏步

**铁律**：先定每镜头叙事节拍数（一个动作 = 一个节拍），再定时长。**不要先定时长再硬塞叙事**。

### 铁律 3：短视频的剪辑节奏

短视频平台的剪辑节奏共识：**每 2-4 秒一个 cut，3 秒内必须有 hook**。这意味着：

| 平台总时长 | 推荐镜头数（cut 数） | 平均每镜 |
|---|---|---|
| 15 秒（抖音/Reels 极短） | 4-6 个 | 2.5-3.7 秒 |
| 30 秒（抖音/Reels 标准） | 6-10 个 | 3-5 秒 |
| 45-60 秒（YouTube Shorts / 中长） | 8-15 个 | 3-6 秒 |
| 60-180 秒（深度内容） | 15-30 个 | 4-8 秒 |
| 微短剧单集（90-180 秒） | 12-25 个 | 5-10 秒 |

**例外**：纪录片式氛围片 / 慢电影风格可以违反这个节奏（单镜头 8-15 秒），但需要**用环境运动 + 微动维持注意力**——见铁律 4。

### 铁律 4：每个镜头必须有"目的"

每个镜头都要回答两个问题：**为什么需要这个镜头？为什么这个镜头要这么长？**

如果一个镜头删掉，整段叙事还成立 → 这个镜头是多余的。
如果一个镜头时长砍半，信息没丢 → 这个镜头太长。

每个镜头的"目的"分 6 类（拍摄前必须明确定哪一种）：

| 目的 | 镜头特征 | 典型时长 |
|---|---|---|
| **建立**（establishing） | 全景/广角，交代环境/位置/时空 | 2-4 秒 |
| **介绍**（introducing） | 中景/近景，引入新主体 | 1-3 秒 |
| **动作**（action） | 主体在做事，运动驱动 | 3-6 秒 |
| **反应**（reaction） | 特写/近景，情绪/物理线索 | 1-3 秒 |
| **揭示**（reveal） | 信息浮现，悬念/转折 | 2-5 秒 |
| **氛围**（atmosphere） | 环境运动，无主线动作 | 3-8 秒 |

## 拆镜头工作流

### Step 1：抓核心 hook

读完用户输入后，第一句话回答：**"这段视频的 hook 是什么？"**

hook 必须在前 3 秒出现。它可以是：
- 视觉冲击（颜色、动作、构图反差）
- 信息悬念（"接下来会发生什么"）
- 情绪锚点（一个表情、一个手势）
- 反差对比（前后/今昔/角色对立）

**没有 hook 的短视频 = 完播率 < 30%**。如果用户输入里找不到 hook，主动建议补一个。

### Step 2：定三幕结构

短视频通用结构（无论时长）：

| 段 | 占比 | 目的 |
|---|---|---|
| **Hook（钩子）** | 前 20% | 抓注意力，让人不划走 |
| **Value（主体）** | 中间 60-70% | 兑现 hook 承诺，推进叙事/信息 |
| **Payoff（收尾）** | 末 10-20% | 给闭环，留 CTA / 情绪余味 / 转折 |

按总时长分配：

| 总时长 | Hook | Value | Payoff |
|---|---|---|---|
| 15 秒 | 0-3 秒 | 3-12 秒 | 12-15 秒 |
| 30 秒 | 0-5 秒 | 5-25 秒 | 25-30 秒 |
| 60 秒 | 0-8 秒 | 8-50 秒 | 50-60 秒 |
| 90-180 秒（微短剧）| 0-15 秒 | 15 至倒数 15 秒 | 末 15 秒 |

### Step 3：定每段镜头数

按铁律 3 的总镜头数 + Step 2 三幕占比分配：

例：30 秒短视频，推荐 8 个镜头：
- Hook（0-5 秒）：1-2 个镜头
- Value（5-25 秒）：4-6 个镜头
- Payoff（25-30 秒）：1-2 个镜头

### Step 4：定每镜的目的、景别、运镜、时长

每个镜头按以下模板填：

```
镜头 #X · [起止秒数]
- 目的：[建立/介绍/动作/反应/揭示/氛围]
- 景别：[全景/中景/近景/特写]
- 运镜：[Static / Slow push-in / Pan / ...]（用 ltx-camera-movement skill 词典）
- 时长：[X 秒]
- 视觉重点：[这个镜头要让观众看到什么]
- 接续逻辑：[与前一镜的关系——cut / 同场切角度 / 跨时空 / 接续动作]
```

### Step 5：定每镜的 AI 生成路径

每个镜头标注下游交给哪个 prompt skill：

| 镜头类型 | 推荐生成路径 |
|---|---|
| 静态氛围（火光、雪花、烟雾） | `ltx-t2v-prompt`（直接文生视频）|
| 单主体 + 简单动作 | `ltx-i2v-prompt`（先出图，再图生视频）|
| 起止状态明确（转身、表情切换、产品揭示） | `ltx-flf-prompt`（首尾帧）|
| 连续多镜头叙事（trailer/广告/微剧） | `gpt-image2-seedance-storyboard`（九宫格分镜 + Seedance 链路） |
| 镜头复杂、要求精确控制 | 拆成多个 sub-shot 分别用 i2v/flf 生成 |

### Step 6：跨镜头一致性检查

镜头清单出完，必须检查 4 个连续性维度：

| 维度 | 检查项 |
|---|---|
| **角色** | 同一人物在不同镜头里是否描述一致（发色、服装、年龄）|
| **场景** | 同一场景在不同镜头里光线/色调/陈设是否一致 |
| **时间** | 镜头之间时间线是否合理（白天-夜晚不能无理由切换）|
| **空间** | 角色位置/朝向是否符合"180 度法则"（不要让角色在两个镜头里反向）|

任一维度漂移 → 在镜头说明里加一致性 anchor（"承接镜头 X 的暖光"、"延续镜头 Y 的旗袍"）。

### Step 7：可生成性预判（哪些镜头交给 AI 生成必崩）

每个镜头按以下表评估，命中即给替代方案：

| 镜头特征 | AI 处理难度 | 替代方案 |
|---|---|---|
| 多角色互动（2 人以上同框对戏）| 🔴 极难 | 拆成单人镜头 + 反打剪辑 |
| 复杂物理（爆炸、流体撞击、玻璃破碎）| 🔴 极难 | 改用现成素材 / 第三方特效插入 |
| 快速运动 + 镜头跟拍 | 🔴 极难 | 改用 static + 主体微动 |
| 手指精细操作（开锁、按按钮、写字）| 🟡 难 | 避开手指特写，改中景 |
| 文字 / Logo 在主体上 | 🟡 难 | 后期叠加，不让 AI 生成 |
| 人脸特写超过 5 秒 | 🟡 难 | 拆成 2-3 个短镜头 |
| 大幅转身（>90°）| 🟡 难 | 拆成"转身前"+"转身后"两镜，cut 切换 |
| 单主体 + 缓慢动作 + 简单环境 | 🟢 容易 | — |
| 环境运动（雪、雨、火、烟） | 🟢 容易 | — |
| 静景 + 微动（呼吸、衣摆飘动） | 🟢 容易 | — |

**总原则**：会用 AI 视频的人，不是会写最复杂 prompt 的人，是**知道什么时候放弃 AI、改用真实拍摄/3D/素材**的人。

## 常见错误

### 错误 1：直接按时长定镜头数（不看叙事密度）

用户："30 秒视频，每镜 5 秒，6 个镜头吧"——错。
正确：先看 hook 是什么、有几个叙事节拍、再反推镜头数。

### 错误 2：让 AI 做不擅长的事

用户："想要 10 秒视频，两个角色对话"——AI 视频模型几乎都做不好双人对话同框。
正确：拆成"角色 A 说话特写 + 角色 B 反应特写"两个镜头，剪辑拼接。

### 错误 3：忽视画幅

用户："我做了 9:16 抖音视频"，但你按 16:9 横屏构图拆镜——构图全错。
正确：先确认画幅，再选适合该画幅的运镜（9:16 慎用横向 pan，16:9 慎用极特写）。

### 错误 4：把"分镜画稿"和"镜头清单"混淆

分镜画稿 = 每个镜头的视觉草图（用 flux2-storyboard / gpt-image2 出图）
镜头清单 = 每个镜头的执行参数（本 skill 输出）

本 skill 只产清单，不产画稿。要画稿用 `flux2-storyboard-prompt` 或 `gpt-image2-seedance-storyboard`。

### 错误 5：用单个 prompt 想生成整段视频

很多人想用一段长 prompt 让模型生成"完整短视频"——错。
正确：**单镜头思维**——每次只让模型做 1 个镜头，最后剪辑拼接。

## 跟其他 skill 的协作

| 上游 | 本 skill | 下游 |
|---|---|---|
| 项目宪法（如 `cuojia-longgu`） | 本 skill 接受项目约束，输出镜头清单 | 逐镜头交给 prompt skill |
| 用户原始想法 / 剧本 | 本 skill 拆解 | 同上 |
| | | `ltx-t2v-prompt`（文生）|
| | | `ltx-i2v-prompt`（图生）|
| | | `ltx-flf-prompt`（首尾帧）|
| | | `gpt-image2-seedance-storyboard`（九宫格）|
| | | `flux2-prompt-generator`（出首帧）|
| | | `realistic-character-prompt`（出人物首帧）|

**典型工作流**：
1. 用户给故事 → 本 skill 拆出 N 个镜头清单
2. 对每个镜头：选生成路径 → 调对应 prompt skill → 出单镜视频
3. 全部出完 → 用户在 CapCut / Premiere 拼接

**注入项目宪法**：如果当前有项目宪法 skill 在场（如 cuojia-longgu），本 skill 在 Step 6 一致性 anchor 中**自动引用项目宪法的视觉/角色约束**——不要重复写一遍，引用即可。

## 写作风格

- 输出始终中文（除非用户明确要英文）
- 镜头清单用 Markdown 表格 + 子弹列表，不要纯散文
- 时长精确到秒（不要"大约几秒"）
- 运镜词必须从 `ltx-camera-movement` 词典里选，不要自创
- AI 难度评级 + 替代方案是必输出项

## 输出纪律

- 不写单镜头 prompt（那是下游 skill 的事）
- 不画分镜图（那是 storyboard skill 的事）
